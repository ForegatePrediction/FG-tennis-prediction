# Poly 网球分类与球员映射研究

> 分类完整性补充：本报告的 8 个入口与开放目录不是全部赛事枚举。后续已改为遍历完整字典与历史，四大满贯和具体赛事清单请以 [Poly 网球完整分类枚举（含历史）](Poly网球完整分类枚举-2026-10-26.md) 为准；本报告保留当时开放状态与球员映射核查结果。

核查日期：2026-10-26，北京时间。开放赛事扫描完成于 01:53，参与者目录分页及分类底表于 02:05 汇总。本报告针对 ForeGate 使用 Poly 直连盘的接入方式：**先以 Poly 的赛事与参与者为覆盖目录，再映射 ForeGate 分类和模型身份**。

赛事发现与预测支持应分别记录。Poly 出现某场比赛，就应进入采集目录；只有球员身份、历史数据、场地与赛制等满足模型要求时，才可以返回可用预测。目录收录不能替代模型覆盖验收。

## 1. Poly 的分类结构

实时 `/sports` 返回以下 8 个带 Tennis 总标签 `864` 的入口。它们混合了巡回赛、单／双打和具体赛事，不能当作互斥的八个联赛。

| 入口 sport | 名称 | sport.id | primaryTagId | series ID | 本轮确认的范围 |
| --- | --- | ---: | ---: | ---: | --- |
| atp | ATP Tour | 45 | 101232 | 10365 | 男子单打；包含挑战赛、资格赛，不能全部视为 ATP 主巡回赛 |
| wta | WTA Tour | 46 | 102123 | 10366 | 女子单打；历史温网事件也可使用该 sport |
| itf | ITF | 187 | 104923 | 11634 | 同一入口包含男子与女子比赛，需进一步识别 |
| atp-doubles | ATP Doubles | 259 | 101232 | 11632 | 男子双打组合 |
| wta-doubles | WTA Doubles | 299 | 102123 | 11633 | 女子双打组合 |
| wimbledon | Wimbledon | 435 | 100290 | 12012 | 赛事系列，横跨男／女单打、双打，以及青少年、资格赛 |
| daviscup | Davis Cup | 787 | 106226 | 12826 | 国家队赛事中的单场单打和双打；抽查 20 个事件中分别为 16、4 |
| bjkcup | Billie Jean King Cup | 788 | 106227 | 12827 | 分类元数据存在；本次系列事件和参与者查询均为 0，尚未确认实际盘口范围 |

来源：[Poly 实时 Sports 元数据](https://gamma-api.polymarket.com/sports)、[官方 Sports 字段说明](https://docs.polymarket.com/api-reference/sports/get-sports-metadata-information)。原始响应与请求时间保存在本项目 `data/market-audit/2026-10-26/taxonomy-scan/`。

需要保留的分类差异：

- ATP 与 ATP Doubles 共用主标签 `101232`，WTA 与 WTA Doubles 共用 `102123`，仅凭主标签不能判断单／双打。
- 温网历史目录 801 个事件的实际 `event.sport` 分布为：ATP 304、WTA 303、男子双打 99、女子双打 95。赛事系列与巡回赛是两个分类轴。
- `seriesType=single` 也出现在 ATP Doubles 系列，不能解释成网球单打。应结合 `event.sport`、明确的 `eventMetadata.format` 和比赛描述判断，冲突保留待核验。
- 当前 42 个开放事件由 `tennisFixtureSource=optic-challenger-qualifying` 明确标出挑战赛资格赛；其余 ATP 事件不能因缺少该字段就认定为主巡回赛正赛。
- 赛事名中的 Juniors 可以识别青少年范围；球员姓名中的 Junior 不可用来判断青少年赛事，已增加回归验证。

## 2. 四大满贯与历史格式

除了上述入口，本轮还核实到以下赛事标签：澳网 `866`、法网 `102106`、温网 `100290`、美网 `100408`。

美网 `100408` 也会附于高尔夫事件，因此不能只通过 “US Open” 名称或该标签认定网球。优先与 Tennis 标签 `864` 及赛事内容交叉确认。本轮 Tennis 的 related-tags 接口返回空数组，不能据此推断不存在子分类。

三个实际历史样本：澳网事件 `16934`、法网 `25935`、美网事件 `41151`，均缺少 `sport`、`series`、`teams`、`eventMetadata`，市场也没有 `sportsMarketType`。但其标题与双方结果标签仍指向单场网球比赛。例如 [美网 Djokovic vs Fritz 原始事件](https://gamma-api.polymarket.com/events/41151)。

因此，“八入口遍历完毕”不等于“Poly 全部历史网球覆盖完毕”。旧格式已在底表中保留为 `legacy_match_candidate`，等待身份和合约核验，不把它们直接混入已确认单场比赛。

其中 **7,177 条为个人型记录，2,442 条为双打组合型记录**；这不是 9,619 名独立球员。Davis Cup 的 42 条中包含个人和组合；温网赛事中的参与者实际归属 ATP／WTA 等目录，温网 roster 为零不代表赛事没有球员。

身份核验发现：

- 1,057 组规范化姓名对应多个 Poly ID。例如 Aaron Gabet 分别出现在 ATP 和 ITF ID 中。它们可能是同一个人跨源重复，也可能存在同名，需外部证据才能合并。
- `providerId` 的来源命名空间不完整，ITF 也常缺失此字段，不能直接当作 TennisMyLife／ATP／WTA 通用 ID。
- 双打组合拥有自己的 ID；不能把 “Hopper/Mitsui” 这类姓氏组合直接拆成两个已核实个人 ID。
- 只使用本事件中唯一的完整姓名或 Poly 明确提供的 `alias`，关联结果标签与参与者。双打别名可解释组合姓名顺序反转，匹配结果保留依据；同名／别名歧义留待核验。
- 当前 614 个单场事件中，613 个可完成双方结果标签到 Poly ID 的关联。唯一未完成者为 `1248224`：结果标签 `Umberto G. Capitanio`，参与者名 `Umberto Giuseppe Capitanio`，缺少明确别名。没有自动猜测缩写。
- 在 591 个符合上述盘口状态条件的单场事件中，590 个完成双方关联。

这是 **Poly 结果标签 → Poly 参与者 ID** 的关联验收。所有注册表的 `canonical_player_id` 暂为空，尚不表示完成 Poly → 历史数据球员身份的跨源映射。

## 5. ForeGate 映射建议

采用多个独立字段保留源信息，后续再设置 ForeGate 的内部分类 ID：

| 信息 | 保留内容 | 用途 |
| --- | --- | --- |
| 体育根类 | Tennis tag 864，原始 tags | 发现网球事件；缺字段事件另行审核 |
| Poly 入口 | sport 字符串和 ID、series 列表 | 保留巡回赛与赛事系列交叉关系 |
| 具体赛事 | league_raw、赛事名称、届次候选 | 后续建立官方赛事与 ForeGate 分类映射 |
| 竞赛属性 | 性别、单／双打、青少年、资格赛、级别及判断依据 | 选择模型、阻止范围误用；未知值保留未知 |
| 对阵 | event ID、参与者 ID、原始姓名／别名 | 匹配历史数据身份，支持前端直接传入的对阵上下文 |
| 合约 | market ID、conditionId、clobTokenIds、原始 outcomes 与顺序、玩法类型、盘口线 | 将预测对应到正确市场及结果一侧 |
| 模型上下文 | 场地、盘制、实际开赛时间 | 必须补齐和核验，不能用分类名称随意默认 |

ForeGate 可以继续从既有赛事详情页直接调用预测 API。分类信息可用于后端识别对阵、补充上下文和选用模型，不需要要求用户先进入我们额外的赛事目录。最终传参规范在完成来源身份映射后制定，本报告不创建虚构的 ForeGate categoryId。

本次样本未建立可靠的 `surface`、`best_of`、室内字段，导出时场地和盘制保持空值。`startDate` 可能是事件创建时间，`endDate` 可能是市场期限，需优先核对 `startTime`／市场 `gameStartTime`，不能直接当作比赛结束时间。参与者 `record=0-0` 不应当作真实交锋历史；`home/away` 不意味着网球存在主客场优势。

Poly 还提供首盘、各盘、总局数、让盘／让局、完赛与冠军等玩法，不能用单场胜率覆盖全部合约。当前 614 场单场胜负盘描述也包含特殊情况下 50/50 等结算条款，后续需要核对退赛／弃权规则与模型“正常完赛条件下胜率”的差异。

## 6. 采集与扩展顺序

1. **动态目录**：Tennis 根标签发现 + `/sports` 元数据补充 + 各 series 交叉检查；监控新入口、未知玩法和字段变化，按 event／market ID 去重更新。不能将本次八入口写成永不变化的白名单。
2. **球员身份**：保持 Poly 源 ID，使用完整姓名、巡回赛、外部资料和经过核验的历史 ID 建立跨源映射；同名、缩写和组合拆分进入待核验清单。
3. **预测范围**：先验收成人 ATP／WTA 单打身份和上下文，再扩大挑战赛、ITF 的免费历史数据。当前 ITF 开放比赛最多，是接近 Poly 覆盖的重点；免费源能否持续更新及其授权范围仍需单独验证。
4. **特殊范围**：双打组合与青少年需要独立历史和建模验证；国家队赛事要识别其中的具体单／双打场次。冠军、盘分、让局等合约另行建模。
5. **覆盖指标**：分别输出发现率、分类率、双方身份映射率、上下文完整率、历史数据可用率、可预测率。缺资料时明确不就绪，不用默认概率制造覆盖。

API 维护发现：本轮旧 `/events` 分页响应已包含 `Deprecation: true` 和 `Warning: use /events/keyset`。已按[官方游标分页文档](https://docs.polymarket.com/api-reference/events/list-events-keyset-pagination)实测新接口两页，确认返回 `events`、`next_cursor`，下一页通过 `after_cursor` 获取且本次无重复。正式日更采集应迁移到游标分页；本轮开放数量来自已完成的旧接口扫描，新接口目前仅做两页连通与游标验证。
