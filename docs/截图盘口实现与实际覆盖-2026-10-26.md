## 截图逐项实现

| 玩法 | 合约数量 | 实现与限制 |
| --- | ---: | --- |
| Moneyline | 1 | 正常完赛条件下双方胜率 |
| Set Handicap | 2 | 双方分别让 1.5 盘；按问题中选手姓名及正负号绑定，处理反转顺序 |
| Total Sets | 1 | 大小 2.5 盘 |
| Total Games | 3 | 大小 21.5／22.5／23.5 局 |
| 第 1 盘胜者 | 1 | 双方第一盘胜率 |
| 第 1 盘总局数 | 3 | 大小 8.5／9.5／10.5 局 |
| 第 2 盘胜者 | 1 | 双方第二盘胜率 |
| 第 2 盘总局数 | 3 | 大小 8.5／9.5／10.5 局 |
| Completed Match | 1 | 返回 unavailable；不使用固定 95% 或比分模型编造完赛概率 |

另外可显式请求全场让局、精确盘分、赢球且达到局差，以及赛制允许的其他盘次／半整数盘口，合计支持 11 类比分玩法。后续盘未进行的概率单列，不能当作任一方输盘。整数走盘、双打和其他非标准赛制仍不支持。

## 接口

`POST /predict/markets` 接收一场比赛的 `tour,a,b,surface,best_of,final_tiebreak_points,format`，可选日期、排名、室内标记、`competition` 和 `markets` 数组。未传 markets 时采用截图 BO3 模板。指定盘口示例：

```json
{"market_type":"tennis_match_totals","line":22.5}
```

所有盘口共用一次比分分布，输出 `summary`、逐项概率、回测质量、条件和缺失原因。一条错误盘口不会使有效的其他盘口丢失。完整请求在 `examples/markets-request.json`；对应假设对阵响应在 `reports/markets-response-example.json`，不能将示例当成实际赛程。

`POST /predict/poly-event` 接收原始 Gamma `event`、`match`、`player_mapping`、`mapping_verified=true` 和映射证据 `source`。`player_mapping` 每方包含 `poly_name` 及可选经过核实的 aliases；match 指定内部球员 ID 和 `competition`。内部球员姓名必须与这些已确认别名对应，不使用模糊同姓匹配。分类、场地及赛制仍需调用方核实，不能只根据 Poly 的 ATP 标签推断。

主模型使用 `format=main_tour_singles`、`competition=main_tour`。独立 ATP 扩展模型也接受 `format=expanded_atp_singles`，其已验证 competition 为 `main_tour`、`challenger_main_draw`、`atp_qualifying`。`tennisFixtureSource` 指向其他范围或与声明矛盾时拒绝给概率。已开始、已关闭、直播中的事件不使用此赛前接口。

响应的 `outcome_predictions` 保留原始选项和 Token 顺序，概率字段名为 `conditional_probability`。规则文本保存于请求／原始证据，响应包含其哈希；`rules_status` 明示尚未自动完成结算规则处理。结果一直包含 `contract_ready=false`，不提供混同退赛、取消和未到达盘次的无条件交易价格。Poly 的 `outcomePrices` 完全不参与模型输入。

## 扩展模型检验

扩展模型在 `models/expanded/current.json`，原主模型不变。2010—2011 年初始化，2012—2022 年拟合、2023 年选择、2024 年校准，2025 年起独立测试。各场使用赛前已安全可得的历史，普通赛事按整周保守延后；不会使用同一赛事后续轮的赛果。

| 胜负测试分组 | 场次 | 准确率 | Log loss | 基础 Elo Log loss |
| --- | ---: | ---: | ---: | ---: |
| Challenger 正赛 | 12,188 | 64.61% | 0.62959 | 0.65176 |
| ATP 资格赛 | 2,372 | 67.37% | 0.60659 | 0.63044 |
| 主巡回赛 | 4,748 | 66.93% | 0.60944 | 0.62884 |

比分层仍为实验模型。胜负、盘胜者和让盘有一定离线依据；部分大小局／大小盘没有优于冻结的历史频率基线。例如 Challenger 正赛大小 22.5 局 Log loss 为 0.70735，频率基线 0.68372，越低越好。接口保留这些盘口计算，但通过 `validation_gate` 标明研究限制，不能声称全部玩法已验证有效。各参数及赛事层级结果见 `reports/atp-expanded-score-backtest.json`。

Completed Match 的规则包括正常完赛、退赛、弃权、完全取消及 14 天内未确定胜者。现有赛果 CSV 中的 RET／W/O 不包含全部计划后取消／未赛的样本，训练一个退赛率并不能替代该合约的完整概率；因此当前明确不输出这个盘口的概率。
