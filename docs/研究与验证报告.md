# ForeGate 网球模型研究与验证报告

核查日期：2026-10-25。模型历史截点：2026-10-24。交付范围：可独立运行的免费数据 ATP/WTA 单打赛前胜负模型，已完成本地下载、训练、推理和 HTTP 测试。尚未启动线上网球定时任务或接入现有生产网关。

## 结论与模型选择

网球模型可行，免费数据足以建立具有可验证效果的第一版。本次实现为 **总体 Elo + 场地 Elo + 多项赛前特征 + 正则化逻辑回归 + 独立年份概率校准**，男女分开。没有使用赔率、付费 API、付费密钥或比赛结束后才知道的当场技术统计作为预测输入。

这是本次实测通过的轻量基线，不声称是所有算法中的最优方案。树模型、逐分 Markov、实时伤病与动态赛程连接没有在本轮实现或比较。

排名确实应当考虑，但排名差不宜直接线性加分。本模型使用排名的对数、积分、数据缺失指示，与 Elo 和场地实力共同估计。权重由历史数据拟合。近期表现同时考虑胜负及相对于赛前 Elo 预期的表现，避免把连续击败弱对手简单等同于状态极佳。

相克关系有三个可实现层面：同场地交锋、超出实力差预期的交锋表现、面对对手持拍手时的近期表现。本轮实现了这些特征；交锋采用时间衰减和向零收缩，样本越少影响越小。**2023 年验证集没有支持加入直接交锋特征，所以最终两套模型均选用 `enhanced_no_h2h`，交锋战绩仅展示。** 这不能推出交锋永远无用，也不能因为用户关心相克而人为提高其权重。

## 论文依据

| 研究 | 与本项目有关的证据 | 本轮采用与限制 |
| --- | --- | --- |
| Vaughan Williams、Liu、Gerrard，2019，[How well do Elo-based ratings predict professional tennis matches?](https://www.ntu.ac.uk/media/documents/research-documents/how-well-do-elo-based-ratings-predict-professional-tennis-matches.pdf) | 比较排名、总体 Elo、场地 Elo 和组合，以及概率校准 | 将总体和场地能力分开；该工作样本是 **2018 温网**，不能把结论直接当作全巡回赛保证 |
| Bunker 等，2024，首发 2023，[A comparative evaluation of Elo ratings- and machine learning-based methods for tennis match result prediction](https://journals.sagepub.com/doi/10.1177/17543371231212235) | 按年度扩展训练并比较 Elo 与机器学习；逻辑回归具有竞争力 | 采用时间顺序检验；论文的重要输入包含赔率差，**其结果不能作为无赔率模型的准确率承诺** |
| Gollub，2021，[Forecasting serve performance in professional tennis matches](https://journals.sagepub.com/doi/10.3233/JSA-200345) | 发接发球估计应考虑小样本和对手强弱，研究结合 Elo 与逐分模型 | 本轮对滚动发接发球数据使用先验平滑，对近期及交锋胜负使用 Elo 残差；**未声称复现论文的全部估计器或 Markov 模型** |

由这些研究推导的实施选择是：先验证赛前概率和数据时间口径，再扩展盘分与局数。发球分胜率不能仅靠比赛胜率反推后，就当作已经验证的大小局模型。

## 免费数据核查

采用 [TennisMyLife 数据库](https://stats.tennismylife.org/tennis-match-database) 及其 [公开文件索引](https://stats.tennismylife.org/api/data-files)。只调用发布方提供的 CSV 下载地址，没有绕过登录或验证码。2010–2026 年年度文件加在赛文件，共 36 个，约 19 MB。保存下载 URL、行数、文件字节和 SHA-256，以便复查。

发布方页面标注免费和 MIT，并注明 ATP 使用官方球员 ID；WTA 是从已有网上 CSV 汇编，可靠性仍需改善。**本次没有独立确认 WTA 全部上游授权链；“免费可下载”不应被解释成我们保证全部上游商业授权。**

其他候选中，tennisdata.app 的下载自动访问遇到 403，且其 [条款](https://tennisdata.app/terms/) 对用途与自动访问有限制，因此没有作为生产源。原 Sackmann 地址及镜像的可用性和非商业许可也使它们不适合作为本轮默认长期来源。

| 处理后的历史范围 | ATP | WTA |
| --- | ---: | ---: |
| 接受的完整比赛 | 42,029 | 39,205 |
| 双方都有排名 | 41,927（99.8%） | 39,035（99.6%） |
| 双方都有发球总分字段 | 41,787（99.4%） | 37,236（95.0%） |
| 有比赛时长 | 41,642（99.1%） | 24,225（61.8%） |
| 有明确室内／室外标记 | 41,904（99.7%） | 462（1.2%） |

“有发球总分字段”不代表所有技术字段都完整或无误。程序进一步检查非负计数、分母及分子关系，不合法的技术统计不参与滚动计算。WTA 的时长和室内标记缺失较多，不能把体能与室内效果描述成已得到完整观测。

独立核对使用 ESPN 公开 JSON 的 **2024 四大满贯单打**。按赛事及规范化完整姓名精确匹配，ATP 466 场、WTA 433 场，共 899 场的胜者与逐盘局分全部一致。仍有姓名不匹配、非标准赛果等未匹配项；这不是全库正确率或完整覆盖率证明，也没有核验所有技术统计、排名及 2026 年所有赛果。结果保存在 `reports/independent-source-check.json`，脚本为 `validate_sources.py`。

赛事级别元数据不是完全可靠，例如原始文件中出现赛事名称和级别标记可疑的组合。当前训练不把级别当数值特征，也不直接用某个级别字段的行数声称覆盖多少大师赛。正式接赛程时应增加经核查的赛事 ID 映射表。

**每日文件抓取与每日新增模型历史分开判断。** 发布方把日期定义为赛事周，不能因为 CSV 中出现不同日期就把它们认定为准确的每场开赛时间。所有赛事赛果均保守延后到：`max(赛事开始 + 时长窗口, 最后源日期 + 1 天)`。普通赛事窗口为七天，级别 F 总决赛八天，来源标记 M/1000/PM/P 的大师／Premier 赛事十四天，G 大满贯十五天，以覆盖两周赛制及周日开赛的情形。这是保守时长假设，不能替代实际结束时间的独立核实。预测特征统一使用赛事开始前已知的历史，同一赛事后轮不会看到前轮或后轮的新增统计。

因此，本次 ATP 最新已接收源日期是 10 月 18 日，保守解锁日期为 10 月 21 日；WTA 最新已接收源日期为 9 月 30 日，解锁日期为 10 月 14 日。武汉、宁波、大阪等更晚记录已下载，但保守窗口要到 10 月 26 日才解锁。报告中的 `source_date` 表示原文件日期，`safe_available_after` 表示保守解锁日，均不等于经独立核实的实际比赛时间。

这牺牲了一部分实时性，适合首版赛前基础胜率，不应被包装成实时后轮模型。后续可用 ESPN 的实际比赛时间交叉验证补齐，但需要解决姓名／ID、赛事和日期映射，不能直接把不同站点球员编号合并。

## 时间验证与实际结果

2010–2011 用于初始化历史。2012–2022 拟合系数，2023 选择特征组和正则强度；随后用 2012–2023 重拟合。2024 只用于概率温度校准。2025 至截止日作为独立测试，不能用该测试集反选参数。按标签的保守可用日期限制拟合和校准，避免跨年尚未结束的赛事标签提前进入训练。

历史 Elo 和滚动状态在测试过程中只用已解锁的过去赛果更新；最终交付系数也固定为上述已评估版本，状态更新至截止日。日更更新历史状态，不意味着每天重新选择一套测试成绩更高的参数。

| --- | ---: | ---: |
| 拟合期比赛数 | 26,756 | 25,004 |
| 特征选择期比赛数 | 2,614 | 2,391 |
| 校准期比赛数 | 2,670 | 2,451 |
| 独立测试比赛数 | 4,748 | 4,541 |
| 最终准确率 | 66.62% | 67.01% |
| 基础 Elo 准确率 | 64.74% | 65.32% |
| 只选排名较高者准确率 | 64.55% | 64.13% |

除准确率外，表中误差指标越低越好。只按排名选胜者是分类基线，没有人为给它赋一个不合理的概率；其样本限双方都有排名。其他概率模型在各巡回赛相同测试样本上比较。

按赛事为单位进行 1,000 次区块 bootstrap，模型相对基础 Elo 的平均 Log loss 差值 95% 区间：ATP `[-0.04073, -0.02166]`，WTA `[-0.02837, -0.01504]`。这支持本测试样本中的改善，不保证以后或其他数据源上继续保持。

| --- | ---: | ---: |
| 2025 | 66.21%，2,462 场 | 66.28%，2,340 场 |
| 2026 至截点 | 67.06%，2,286 场 | 67.79%，2,201 场 |
| 硬地 | 66.40%，2,673 场 | 67.08%，2,822 场 |

WTA 草地样本与效果尤其应继续观察。各组对手实力分布不同，不能直接把子集准确率差当作该场地模型能力的因果结论。

交锋对照：ATP 不含交锋 Log loss 0.61125，含交锋 0.61104；WTA 分别 0.60385 和 0.60382。测试差值很小，且 **2023 验证期均未改善**，因此没有根据测试结果临时改选含交锋版本。核心 Elo／排名版的测试 Log loss 为 ATP 0.61868、WTA 0.60801；增加滚动表现和技术统计后的整体组合有改善，不能据此认定每一个技术字段都单独有效。

完整回测、分组结果、正则候选、交锋对照与校准桶保存在 `reports/atp-backtest.json` 和 `reports/wta-backtest.json`。

## 工程交付与剩余条件

已具备：免费抓取、来源校验、双方历史和场地能力维护、可复现训练、原子模型快照、纯标准库推理、CLI、HTTP、数据过期提示及 GitHub Actions 日更配置。关键测试覆盖同赛事不泄漏、未来赛果不影响过去特征、当场统计不作为当场预测输入、交换选手概率互补、训练与运行计算一致、异常数据及接口输入拒绝。

日更脚本已在本机跑通。GitHub 工作流只是配置文件，目前未发布到新仓库，也未实际建立线上网球调度。HTTP 快照更新后需重启服务。现有生产网关及其他运动没有因为本轮研究而改动。

尚不能承诺的内容包括：免费源永久可用、全网所有比赛齐全、所有历史字段都是当时发布的原始快照、实时伤病和赛程覆盖、后轮即时更新、盘分／让局／大小局预测。历史数据库存在事后修订可能；时间过滤和因果测试能降低程序泄漏，但不能独立证明第三方历史字段的全部时间来源。

合理的下一阶段是先影子运行实际赛前预测，记录生成时间、源快照、输入与赛后结果；同时补齐赛事／球员映射和可核实的准确比赛时间，再评估逐分模型与新时段树模型。生产对外使用前仍需处理上述数据来源条件及赛程接入。
