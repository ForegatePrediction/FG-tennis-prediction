# 按球员预测与姓名兼容（2026-10-26）

## 行为变化

Foregate 的网球 `/predict` 不再必须传 `eventSlug` 或具体联赛。两名在主模型球员池可识别的选手即可预测；`tour=atp/wta` 只选择球员池。保持 GET、CORS、`platform_markets`、`market_results`、`reasons`、语言及 moneyline `home/away` 结构，方便沿用旧前端流程。

```bash
curl -G 'https://gateway.watchlived.cc/predict' --data-urlencode 'type=tennis' --data-urlencode 'tour=WTA' --data-urlencode 'a= QINWEN--ZHENG ' --data-urlencode 'b=Aryna Sabalenka' --data-urlencode 'lang=zh'
```

`auto` 优先使用已审核赛事；没有 slug 或没有收录时按球员返回参考盘口。`players` 明确进行假设对阵，`fixture` 保留原严格赛事要求。已收录但身份矛盾、过期或开赛的记录仍拒绝，避免把无效真实比赛静默改成假设对阵。原来不带 type/view 且显式传 surface 的本地胜负接口仍保留原返回结构；统一网关注入 view=foregate，前端无须改网关域名。

## 姓名与输入

标准化使用 Unicode NFKD、casefold，再过滤分隔标点；忽略首尾和连续空格、连字符、下划线、点号、引号、常见重音及全角拉丁字母。内部 ID 不区分大小写。标准化后仍须唯一；同姓、歧义、未知球员、同一球员对阵自己会明确失败。只有核实过的别名可以跨不同姓名表达映射，不引入相似字符串猜测。球员数据缺失仍然需要免费历史源补齐，名字兼容不等于新增球员覆盖。

`type/tour/lang/mode` 等控制值忽略首尾空格与大小写；参数名使用文档规定的形式。ID 始终为字符串。前端使用 URLSearchParams 编码，不能直接字符串拼接姓名。

## 缺省背景与概率

默认三盘两胜、决胜盘抢七 7 分、室外；缺少场地时按双方 Hard/Clay/Grass 历史场次分别加一、归一化，形成对称权重后汇总三个模型场景。显式参数覆盖这些假设，`assumptions`、`context`、`surface_scenarios` 记录实际采用值。权重不是现实比赛场地的概率。

基础路径标为 `player_baseline`、`fixture_matched=false`、`context_verified=false`。参考三盘配置返回 11 类、35 个盘口；明确市场参数可通过 markets 指定。选定盘的概率保留“未进行到该盘”质量，不能强行归一化。完赛与否沿用历史总体频率，不当作个体伤病风险。

比分模型和训练权重未改变。新缺省背景汇总未独立回测，移除原已知场地测试分数，使用 `player_scenarios_not_independently_backtested` 标记。这里只验证 API 与概率不变量，150 项代码测试通过不表示预测命中率为 100%。所有结果仍为 `contract_ready=false`。

基础路径不返回真实选项绑定。eventSlug/marketId 在该路径只关联页面，不证明已核实当前赛事。前端应显示假设及原因，按玩法类型、线、盘号、让分方向、比分精确匹配，不能按数组位置或最近盘口线贴概率。主模型训练范围、真实赛程审核范围及球员基础对比是不同覆盖概念。

## 本地验证

执行 `python3 -m unittest discover -s tests -v`：150 项通过，包含 11 项新增测试。新增测试验证姓名格式、唯一性冲突、ATP/WTA 推断及分类矛盾、未知赛事回退、严格模式、审核赛事保护、球员顺序镜像、场地混合一致性、指定盘概率质量、单项失败、错误日期／排名／赛制、HTTP/CORS、旧接口返回。原有真实选项 ID 绑定、交换球员顺序及全部玩法测试仍通过。

完整前端参数及模式见 [GET 接入与联调](Foregate-GET接入与联调.md)。
