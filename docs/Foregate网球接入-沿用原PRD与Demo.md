## 本次沿用的流程

1. Foregate 已有详情接口负责赛事信息和盘口，交易流程保持原有职责。
2. 用户打开 AI 或首次点击某个玩法的 AI 标记时，前端 GET 调用统一预测网关。
3. 网关新增 `type=tennis`，预测服务一次计算比赛的多个玩法。
4. 前端按实际玩法类型、盘口线、盘号、选项含义取出结果，后续打开其他玩法复用缓存。
5. 复用悬浮球、✨AI 标记、概率条、模型倾向、依据、关闭浮层及多语言交互。
6. 未覆盖、参数缺失、比赛已开始或请求失败时复用降级展示；不构造概率。

不把“POST 整份 Foregate detail”作为本次主调用方式；现有 `/predict/markets` 和 `/predict/poly-event` 保留为引擎接口及核查工具。

## 对外接口约定

统一域名保持 `https://gateway.watchlived.cc`，路径保持 `/predict`，新增 `type=tennis`。

```text
GET /predict?type=tennis&tour=atp&a=完整球员名A&b=完整球员名B&eventSlug=现有赛事slug&lang=zh
```

- `tour`：`atp`／`wta`；如用 `categoryId`，须使用核实后的分类映射，不能猜测 WTA 的平台 ID。若同时传入两者，必须一致。
- `a`／`b`：来自 `matches.homeTeam.name`／`awayTeam.name`，表示排列顺序，不引入网球主场优势。内部匹配用唯一姓名或已核实的别名，不能直接复用足球的宽松模糊匹配。
- `eventSlug`：使用 detail 已有值，供服务侧查找同一场比赛及其规则背景；不会仅凭相同球员名匹配另一场比赛。
- `lang`：沿用 `zh`／`en`／`vi`。
- 可选透传 `marketId` 作为 Foregate 关联标识；所有平台 ID、Option ID 和 Asset ID 保留字符串。

这里的最小请求成立的前提，是服务侧有可核实的赛事资料。ATP／WTA 分类和球员姓名本身不足以确定场地、盘制和资格赛层级。缺失这些背景时返回明确不可用原因，不能默认全部属于硬地、三盘制正赛。

前端仍只展示 ATP／WTA；场地、赛事层级、盘制、抢七规则及球员历史由预测服务维护和核验。当前尚缺自动维护完整赛事背景的流程。

## 返回和玩法对应

- 保留旧接入的 `A`、`B`、`matched_exact`、`platform_markets`／`markets`、`reasons` 结构习惯。
- 按实际 `sportsMarketType` 或分类配置中的 `marketSportsType` 识别玩法；两个字段并存且不一致时拒绝映射。
- 同类玩法按 `line`、`set_number`、让分球员及精确比分区分，不能仅按玩法类型选第一条或最接近 50% 的盘口。
- `yesOptionTitle`／`noOptionTitle` 决定选项含义；moneyline 的 Yes／No 可以分别代表两名球员，不等于布尔事件。
- 同一场多玩法由同一比分分布推导；Poly 的市场价格、`chance`、成交量不作为模型概率。
- 保留质量、条件和缺失原因。期数未到达概率不能隐去；是否完赛标明是历史整体基线。
- 未覆盖玩法不进入可展示概率集合，可在独立不可用列表中给出原因，与旧 Demo 的降级判断相容。
- 浏览器缓存按赛事、模型快照、比赛背景及语言区分，切换赛事、盘口参数或开赛后不能复用旧结果。旧 Demo 固定比赛的 `sport|lang` 缓存键不直接复制到真实多赛事场景。
